## Предлог
Внутренние заметки для участников и агентов. Используйте `README.md` как общедоступный источник достоверной информации о примерах API и ограничениях, с которыми сталкиваются пользователи. Команды разработки находятся в `package.json`, а браузерные снимки и диагностика описаны в разделе «Текстовые корпуса и диагностика» в `README.md`.

### Команды
Список команд, включая проверки упаковки, находится в `package.json`.

### Важные файлы

- `package.json` — опубликованные точки входа теперь нацелены на `dist/layout.js` + `dist/layout.d.ts`; сохраняйте поверхность пакета/экспорта согласованной с исходящими файлами
- `tsconfig.build.json` — конфигурация отправки во время публикации для `dist/`
- `scripts/package-smoke-test.ts` — проверка потребителя JS/TS на уровне архива для опубликованной формы пакета.
- `src/layout.ts` — основная библиотека; сохраняйте `layout()` быстрым и легким в распределении
- `src/anaанализ.ts` — нормализация, сегментация, правила склеивания и этап анализа текста для `prepare()`
- `src/measurement.ts` — среда выполнения измерения холста, кеш метрик сегмента, коррекция эмодзи и прокладки профиля механизма.
- `src/line-break.ts` — внутреннее ядро обхода строк, совместно используемое API-интерфейсами с богатой компоновкой и счетчиком строк горячего пути.
- `src/bidi.ts` — упрощенный помощник по метаданным двунаправленного текста для расширенного пути `prepareWithSegments()`.
- `src/test-data.ts` — общий корпус страниц/проверок и тестов точности браузера.
- `src/layout.test.ts` — небольшие устойчивые инвариантные тесты для экспортированных API подготовки/макета.
- `страницы/точность.ts` — проверка браузера плюс построчная диагностика
- `status/dashboard.json` — машиночитаемая основная панель состояния, полученная на основе проверенных снимков точности и эталонных снимков.
- `accuracy/chrome.json` / `accuracy/safari.json` / `accuracy/firefox.json` — проверенные строки необработанной точности.
- `pages/benchmark.ts` — сравнение производительности
- `benchmarks/chrome.json` / `benchmarks/safari.json` — проверенные текущие снимки тестов
- `corpora/dashboard.json` — машиночитаемая полная информационная панель корпуса, полученная на основе снимков и примечаний корпуса.
- `corpora/representative.json` — проверенные репрезентативные строки привязки корпуса.
- `corpora/chrome-sampled.json` / `corpora/chrome-step10.json` — проверенные снимки корпуса Chrome.
- `pages/diagnostic-utils.ts` — общие диагностические помощники, безопасные для графем, используемые страницами проверки браузера.
- `scripts/pre-wrap-check.ts` — небольшая постоянная очистка браузера-оракула для нестандартного режима `{ whiteSpace: 'pre-wrap' }`
- `pages/demos/index.html` — общедоступная статическая демонстрационная целевая страница, используемая в качестве корня сайта GitHub Pages.
- `pages/demos/bubbles.ts` — демонстрация пузырьковой термоусадки с использованием богатого нематериализующегося средства обхода диапазона строк.
- `pages/demos/dynamic-layout.ts` — редакционный разворот фиксированной высоты с непрерывным потоком в две колонки, маршрутизацией заголовков с учетом препятствий и перекомпоновкой в реальном времени на основе логотипа.

### Замечания по реализации

- Опубликованный пакет включает в себя сборку ESM из `dist/`; `dist/` — это вывод времени публикации, а не проверенный источник.
- Обеспечьте честность импорта исходного кода библиотеки во время выполнения с помощью спецификаторов `.js` внутри файлов `.ts`. Это позволяет простому эмитту `tsc` создавать правильный JS и `.d.ts` без шага перезаписи объявления.
- `prepare()` / `prepareWithSegments()` выполняют только горизонтальную работу. `layout()`/`layoutWithLines()` явно принимают `lineHeight`.
- `setLocale(locale?)` перенаправляет поднятый сегментатор слов для будущих вызовов `prepare()` и очищает общий кэш. Используйте его перед подготовкой нового текста, если приложению требуется конкретная локаль Intl.Segmenter вместо используемой по умолчанию во время выполнения.
- `prepare()` должен оставаться непрозрачным дескриптором быстрого пути. Если странице/скрипту нужны массивы сегментов, это обычно должно проходить через `prepareWithSegments()` вместо повторного раскрытия внутренних компонентов основного подготовленного типа.
- `walkLineRanges()` — это API пакетной геометрии с расширенными путями: без материализации строк, но по-прежнему браузерная ширина линий/курсоры/состояние произвольного дефиса. Предпочитайте его частным ходункам для работ по утеплению или компоновке агрегатов.
- `prepare()` внутренне разделена на этап анализа текста и этап измерения; сохраняйте ясность в этом шве, но сохраняйте простой общедоступный API, если только требования не вынуждают внести изменения.
- Модель внутреннего сегмента теперь различает как минимум восемь типов разрывов: обычный текст, сворачиваемые пробелы, сохраненные пробелы, табуляции, неразрывное склеивание (проходы в стиле `NBSP` / `NNBSP` / `WJ`), возможности разрывов нулевой ширины, мягкие дефисы и жесткие разрывы. Не сворачивайте их обратно
